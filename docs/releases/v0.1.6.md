Your terminal now sees what an agent on the host is doing, attaching to
an ended session no longer spills garbage into your shell, and `osewa
kill` cleans up several sessions at once.

- **Agent status reaches your terminal.** Terminals that read OSC 7501,
  like Rex, show when an agent is working, blocked or done. Through
  `osewa attach` that status stayed on the host. Each live status now
  reaches your terminal as an OSC 7501 that osewa rebuilds from the
  report's fields, so the host can't slip other bytes in. It says what a
  blocked agent needs (permission, an answer, a login), and the notice
  in attach says so too. Leaving the session clears it, so a tab doesn't
  keep showing a program it no longer hears from. Thanks to
  [@matchai](https://github.com/matchai).
  ([#20](https://github.com/rjyo/osewa/issues/20),
  [#24](https://github.com/rjyo/osewa/issues/24))
- **Attaching to an ended session.** A session whose program exited stays
  listed for a day so its last screen can be read. Attaching to one
  printed your terminal's replies to osewa's color questions into your
  shell (`^[]4;0;rgb:…`), after a wrong "another window on this device
  owns this session". Attach now waits for those replies before it
  leaves, and shows the last screen with no owner notice.
  ([#19](https://github.com/rjyo/osewa/issues/19))
- **`osewa kill` takes several ids**, and goes on past one it can't end.
  `osewa kill --exited <host>` ends every session whose program has
  exited. ([#18](https://github.com/rjyo/osewa/issues/18))

The status's kind and title, and the owner notice fix, need this release
on the host too; the rest needs it where you attach. This release
interoperates with v0.1.5 (`p0-s1`).
