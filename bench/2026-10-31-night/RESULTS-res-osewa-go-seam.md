## Typing during a forward download (Docker)

From e2e TestForwardPriority, 2026-10-30, image a3effdf-dirty.
Echo of keystrokes typed into `cat` in a session over 1 Mbit/s, 100 ms
RTT, 1% loss (server egress shaped), 60 keystrokes each, with and
without a forward downloading as fast as it can on the same connection.
Budget: p95 with a forward at most the no-forward p95 + 250ms, measured in
the same run. That margin is the designed cost of a bulk forward on this
link: one window of queue (about 1 BDP, 100 ms) plus TCP loss recovery
behind it at 1% loss. This run: budget 467ms, met; ratio 1.27x.

## osewa vs ssh (Docker)

From e2e TestVsSSH, 2026-10-30, image osewa-e2e:dev. Client on the host, server in a
container, both protocols through the same published ports. The
server's egress is shaped per link (netem, with the path's buffer as
its queue limit); ingress is not. Connect + run: a new connection
running `true` (ssh without a ControlMaster). Download: `cat

## Resource use (Docker)

From e2e TestResourceUse, 2026-10-31, osewa 0e9aae2-dirty (current tree; image unlabeled), image osewa-go-seam. The mosh rig: a server
and a client container, 10 Mbit/s and 100 ms RTT both ways. One terminal
per tool, attached as people run it (osewa attach, ssh -tt, mosh-client).
CPU is the share of one core over a 15s window after connecting (user +
system time from /proc); memory is the peak summed RSS sampled each
second. Host: osewa server and the session's holder, sshd (listener and
connection processes), mosh-server. Client: osewa, ssh, mosh-client.
The shell and the workload are not counted. Typing is drive's 10
keys/s into cat; W1 is scrolling log lines, W2 styled full-screen
repaints (bench/workload.go). Program wrote: what the workload got
onto its terminal, per second; a flood writes as fast as the far end
drains it, and osewa and mosh drain it at once (they send screens,
not every byte), while ssh drains it only as fast as its link
carries it, so compare a flood's CPU per MB written.
