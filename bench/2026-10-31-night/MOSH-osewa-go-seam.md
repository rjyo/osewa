# osewa vs mosh

Generated by `make bench-mosh` (e2e/mosh_test.go, TestMoshHeadToHead) on 2026-10-30, osewa 0e9aae2-dirty (current tree; image unlabeled), image osewa-go-seam.

## Setup

- Two containers on one Docker network: the server (osewa server,
  mosh-server 1.4.0) and the client (osewa attach, mosh-client 1.4.0).
- Both eth0 egresses shaped with netem: 10 Mbit/s, 50 ms each way (100 ms
  RTT), loss as named per table, so both directions see the profile.
- Each client runs in a PTY under `osewa-bench drive`, which renders its
  output with libghostty, the way a terminal would, and measures what is on
  that screen. Remote output comes from `osewa-bench gen`, which stamps
  every 8 lines with the time; containers share the kernel clock, so
  screen age is now minus the newest stamp visible.
- mosh runs with its default adaptive prediction. osewa runs `osewa attach`
  as shipped at this commit (prediction per its own default).

## Measurements

- **Keystroke to glyph**: 200 letters typed into `cat` at 100 ms
  intervals (Enter every 30); time until the letter is on the cursor's
  line, predicted or echoed. Never shown = not within 5 s.
- **Screen age during flood**: the remote writes as fast as it can for
  15 s; screen age sampled every 20 ms. W1 is scrolling log lines (`cat`),
  W2 heavily styled lines with full-screen repaints, W4 real TUI frames
  (htop-like table, syntax-highlighted code; bench/w4.go). Workloads are
  in bench/workload.go; screen snapshot sizes in bench/RESULTS.md.
- **Recovery after network change**: output at 20 kB/s; the client
  container is disconnected for 5 s and reconnected with a new IP; time
  from reconnection until the screen is under 1 s old and stays so for 5 s
  (watched for 77 s). One run per profile, so this row is noisy: expect
  the order to flip between runs when the two are within a second.
- **Reattach from a new client process**: a session prints 20 kB/s; a new
  `osewa attach` process starts; time until its screen is under 1 s old,
  net of `docker exec` overhead. mosh-server serves only the
  mosh-client that started it, so mosh can't.
- **Bytes per minute**: server egress bytes (eth0 tx) while the remote
  paints W2 at 50 kB/s, scaled to a minute.

"Better" is lower; within 10% or 5 ms is a tie.
